# TradingView 趋势投资 Skill 与每日选股报告设计

## 目标

把仓库中的《趋势投资》课程笔记蒸馏为个人 Codex skill，并在当前 Codex 任务中创建每天北京时间 08:00 运行的本地自动任务。任务只使用本机 Chrome 中的 TradingView，生成 A 股、港股和美股的趋势投资观察报告。

日报的首要用途是提前发现接近枢纽点的股票，方便用户自行核对并设置条件单。日报也提示上一交易日首次触发买点的股票，但不替用户下单，不执行任何证券交易。

## 数据与运行边界

- TradingView 是唯一的行情、图表、行业和成交量数据源。
- 不调用其他行情 API、行情库或第三方股票数据网站补齐缺失信息。
- 自动任务通过本机 Chrome 的现有 TradingView 会话操作股票筛选器和图表。
- 报告使用 TradingView 已完成的最近一个交易日数据。北京时间 08:00 时，三地市场的上一交易日均已收盘。
- TradingView 无法访问、登录失效、页面结构无法可靠读取或某市场数据缺失时，报告明确指出失败范围；不得用缓存、旧结果或其他来源冒充当日结果。
- 报告是趋势筛选和风险测算结果，不是自动交易指令。

## 调度与通知

- 每天北京时间 08:00 运行。
- 结果发到创建自动任务的当前 Codex 任务，并触发正常任务通知。
- 只要三个市场中至少一个市场存在新的完整交易日数据，就生成正常日报。
- 周末或三个市场都没有新收盘数据时，只发送：“今日无新增收盘数据，沿用上一交易日观察名单。”不重复完整报告。

## TradingView 初筛

每天对三个市场分别执行以下初筛：

| 市场 | 市值下限 | 币种 |
| --- | ---: | --- |
| A 股 | 400 亿 | CNY |
| 港股 | 400 亿 | HKD |
| 美股 | 400 亿 | USD |

共同条件：

- 普通股。
- 价格高于 50 日简单移动平均线。
- 50 日简单移动平均线高于 150 日简单移动平均线。
- 150 日简单移动平均线高于 200 日简单移动平均线。

初筛只建立候选池，不等同于买入信号。

## 大盘基准

- A 股统一使用沪深 300 指数。
- 港股科技、互联网、软件、半导体等科技相关行业使用恒生科技指数；其他行业使用恒生指数。
- 美股科技相关行业使用纳斯达克 100 指数（NDX）；其他行业使用标普 500 指数。
- 行业归类以 TradingView 显示的板块和行业为准。

## 图表复核

对初筛候选逐只执行：

1. 先看周线，判断对应大盘与个股的长期阶段。
2. 再看日线，识别 VCP、稳固期、最终收缩、枢纽点、支撑位和压力位。
3. 读取 TradingView 的成交量、相对成交量或时间相对交易量，作为突破状态信息。
4. 检查放量大跌、跌破长期均线、跳空下跌、高位异常阴线等危险信号。
5. 计算当前价相对枢纽点的距离、至支撑位的潜在亏损、至压力位或 2R 目标位的预期盈利及盈亏比。

## 100 分评分

评分只评价课程理论下的形态质量和风险，不把“是否已经突破”本身计入分数。

### 大盘环境：15 分

评价股票对应的大盘基准是否处于第二阶段。该项只评价大盘，不重复评价个股均线。

### 个股第二阶段趋势模板：20 分

综合评价：

- 价格位于 50、150、200 日均线上方。
- 50 日均线高于 150 日均线，150 日均线高于 200 日均线。
- 150、200 日均线向上。
- 高点和低点逐步抬高。
- 整体呈现大涨小回，而非小涨大回。

均线证据只在本项计分，不再因“个股处于第二阶段”重复加分。

### 相对强度与行业地位：10 分

综合评价：

- 股价接近一年高点，或至少较一年低点上涨 30%。
- 走势强于对应的大盘基准。
- 是否属于行业领头羊或顶级竞争者。

### VCP 整体结构：15 分

综合评价：

- 存在至少两到三次可辨认的稳固/收缩。
- 波动幅度总体逐次缩小。
- 回调时成交量趋于收缩。
- 形态持续时间足以完成筹码换手；约三个月是优质特征，但不是机械硬门槛。

### 最终收缩：20 分

- 最终收缩幅度不超过 8%时，可正常计分并参与买点判断。
- 最终收缩幅度大于 8%且不超过 12%时，只能进入观察名单，必须醒目标注：“因最终收缩幅度为 X%，超过 8% 标准而降级观察。”
- 最终收缩幅度超过 12%时，从买点和观察名单中剔除。
- 同时评价最终收缩是否持续至少三个交易日，以及回调是否缩量。

### 止损与盈亏比：20 分

- 以最近枢纽或稳固区低点作为主要支撑位，止损参考价放在支撑位下方少许。
- 潜在亏损不超过 5%时可获得该项高分。
- 潜在亏损大于 5%且不超过 8%时降低该项得分，但仍可参与买点判断。
- 潜在亏损大于 8%且不超过 12%时该项不得分，只能进入观察名单并注明降级原因。
- 潜在亏损超过 12%时剔除。
- 预期收益风险比至少 2:1 为合格。若形态已触发但赔率不足 2:1，仍在“今日新触发买点”中列出，并醒目标注：“买点已触发，赔率不足 2:1，不建议介入。”

## 枢纽突破与成交量状态

枢纽突破和成交量不纳入 100 分评分，但作为用户下单前的状态信息：

- 是否已经突破枢纽点。
- 枢纽价、当前价及二者距离。
- 当日相对成交量。
- 量能状态：充足、一般或不足。
- 是否仍在合理买入区间。

相对成交量建议解释为：不低于 1.2 为充足；1.0 至 1.2 为一般；低于 1.0 为不足。该标签只辅助用户确认，不自动替用户否决或执行交易。

## 接近买点观察名单

这是日报的核心部分，按 A 股、港股、美股分组，每个市场最多列 10 只。

候选必须满足：

- 已通过 TradingView 初筛。
- 个股大体处于第二阶段。
- 当前价位于枢纽点下方 8%以内。
- 最终收缩幅度不超过 12%。
- 没有放量大跌、跌破长期均线等明显危险信号。
- 综合评分至少 60 分。

排序依次考虑综合评分、潜在亏损、距离枢纽点的远近和形态完整度。

优先级解释：

- 80–100 分：高优先级，形态较完整，等待突破确认。
- 70–79 分：正常观察，仍有一两项条件不理想。
- 60–69 分：低优先级，必须明确写出缺失条件。
- 低于 60 分：不进入观察名单。

对应大盘尚未进入第二阶段时，强势个股仍可保留在观察名单中，以便发现下一轮领头羊，但必须标注“大盘环境尚未确认”。

每只股票直接包含：

- 股票名称，不显示股票代码。
- TradingView 行业。
- 当前价、枢纽价、距枢纽点百分比。
- 条件单参考触发价或触发区间；仅供用户人工设置条件单。
- 支撑位、止损参考价和潜在亏损百分比。
- 压力位或 2R 目标价、预期盈利百分比和盈亏比。
- 最终收缩幅度。
- 100 分评分、优点、缺失条件和主要风险。
- 适用时显示 8%–12%收缩或 8%–12%潜在亏损的降级提示。

## 今日新触发买点

这是次要提示部分，只报告新发生的突破，避免重复推送用户大概率已经处理过的旧信号。

判定条件：

- 股票此前位于观察名单或满足观察名单条件。
- 最近一个完整交易日首次突破枢纽点。
- 当前价位于枢纽点上方 8%以内。
- 潜在亏损不超过 8%。

对应大盘尚未进入第二阶段时，突破仍作为事实列出，但必须标注“大盘不在第二阶段，不建议介入”。

首次运行没有历史日报可比较，因此回看最近五个交易日，列出仍处于合理买入区间的突破股票，建立初始基线。之后只报告最近一个完整交易日首次突破的股票。已报告过的突破不重复作为“新触发”推送。

每只股票使用与观察名单相同的字段，并额外显示突破日期、突破状态和相对成交量状态。

股票一旦首次突破，就从观察名单移动到“今日新触发买点”。当日涨幅较大并不自动排除，只要当前价距枢纽点不超过 8%且至支撑位的潜在亏损不超过 8%。超过合理区间时标注“已偏离低风险买入区”，不再作为当前买点推荐。

## 压力位与目标价

- 存在明确上方压力位时，使用 TradingView 日线图上最近的有效波段高点。
- 预期盈利百分比按压力位相对当前价的上涨空间计算。
- 最近压力位提供的收益不足潜在亏损的两倍时，显示赔率不足警告。
- 股票已创新高且上方没有明确压力位时，不虚构压力位，报告“无明显上方压力”。
- 无明确压力位时，以潜在亏损的两倍计算保守的 2R 目标价，并明确标注它是“2R目标价”，不是压力位。

## 日报结构

1. 日期和数据截止时间。
2. 三个市场对应基准的阶段摘要。
3. 接近买点观察名单，按市场分组，每市场最多 10 只。
4. 今日新触发买点，按市场分组；符合者全部列出。
5. 数据读取异常、休市或需要用户复核的说明。

不设置独立的“每只股票报告”章节；股票详细字段直接放在“接近买点观察名单”或“今日新触发买点”的对应条目内。

## Skill 设计

Skill 采用标准的渐进式披露结构：`SKILL.md` 只保留触发条件、路由、核心边界和主流程；课程全文、蒸馏规则、案例、TradingView 操作细节和可编辑模板分别存放，Agent 只在当前步骤需要时读取。

```text
tradingview-trend-investing/
|-- SKILL.md
|-- agents/
|   `-- openai.yaml
|-- references/
|   |-- course-notes.md
|   |-- strategy-rules.md
|   |-- scoring-rubric.md
|   |-- tradingview-workflow.md
|   |-- casebook.md
|   `-- images/
|       `-- selected-case-images
|-- assets/
|   |-- daily-report-template.md
|   |-- no-new-data-template.md
|   `-- data-failure-template.md
`-- scripts/
    `-- calculate-trade-metrics.py
```

### `SKILL.md`

- 使用可发现且不过度宽泛的名称和描述。
- 说明该 skill 只在使用“扫地僧”趋势投资体系，通过 TradingView 筛选或复核 A 股、港股、美股时触发。
- 声明 TradingView 是唯一行情和图表来源。
- 路由 Agent 按需读取规则、评分、案例、UI 工作流和报告模板，而不是每次加载全部资料。
- 明确禁止自动下单；条件单价格仅作为用户人工确认的参考信息。

### 课程原始笔记

`references/course-notes.md` 保存仓库课程笔记的完整文本版本，作为理论争议或细节缺失时的最终参考。保留章节结构、原案例名称和原始图片文件名。对案例库实际使用的精选图例，把 Obsidian 图片链接改为 skill 内可解析的相对链接；对没有随 skill 打包的其余截图，把嵌入链接改成清晰的“原图文件名”来源标记，不制造失效的相对链接。Agent 日常运行不默认加载全文，只在蒸馏规则无法回答、需要核对原意或用户明确要求查看课程依据时读取相关章节。

### 蒸馏规则

`references/strategy-rules.md` 保存日常运行需要的精炼规则：

- 四阶段及第二阶段趋势模板。
- VCP、稳固期、最终收缩和枢纽点。
- 大盘与个股的对应关系。
- 支撑位、压力位、止损、2R 和危险信号。
- 领头羊、顶级竞争者和相对强度判断。
- 本设计中经用户调整的 8%与 12%阈值，明确标注为本 skill 的实战口径，避免与课程原始 5%示例混淆。

`references/scoring-rubric.md` 保存 100 分评分表、观察名单门槛、降级规则、买点有效区间及逐字段计算方法。评分规则只在这里维护，`SKILL.md` 和模板不重复定义一套可能漂移的分数。

### TradingView 工作流

`references/tradingview-workflow.md` 保存三个市场的筛选条件、指数映射、周线与日线检查顺序、相对成交量字段、页面异常恢复步骤和停止条件。页面改版时只需更新此文件，不需要改写课程规则。

### 案例库

`references/casebook.md` 从原笔记提炼可检索案例，每个案例包含“适用问题、图表观察、正确结论、常见误判、原笔记章节和相关图片”。首版至少包括：

- NVIDIA：支撑位、压力位和高风险追价。
- 腾讯：杯柄/枢纽突破及风险收益比。
- JetBlue：四阶段识别。
- eBay：假突破和放量下跌危险信号。
- Dicks Sporting：VCP 多次收缩和突破。
- 小米：从观察、收缩到完整交易系统的综合案例。
- NVIDIA 或 Apple：移动止损、自然调整和加仓的补充案例。

`references/images/` 只复制案例库实际引用、能改变判断的代表性图例，不机械复制全部 168 张、约 108 MB 的截图。案例库必须能从案例名称快速定位到原始课程章节；Agent 需要更多上下文时再读取 `course-notes.md`，并可凭其中保留的原图文件名回到源仓库核对未打包图片。

### 可编辑模板

`assets/daily-report-template.md` 保存正常日报的稳定字段顺序、市场分组和单股条目格式。用户以后要改变栏目、排序、措辞或警告样式时，优先修改模板，而不是改动策略规则。

另外提供：

- `assets/no-new-data-template.md`：三地没有新收盘数据时的简短消息。
- `assets/data-failure-template.md`：TradingView 登录失效、页面不可读或部分市场失败时的报告格式。

模板只定义输出形状，不重复维护评分算法。

### 确定性计算脚本

`scripts/calculate-trade-metrics.py` 只执行可复核算术：距枢纽点百分比、潜在亏损、预期盈利、盈亏比和 2R 目标价。脚本不访问网络、不获取行情、不判断图形；所有输入必须来自本次 TradingView UI 读取结果。

Skill 保持正常自动发现。自动任务的提示词显式要求使用该 skill，并要求按需读取 `daily-report-template.md`、`strategy-rules.md`、`scoring-rubric.md` 和 `tradingview-workflow.md`。

## 测试与验收

### Skill 验证

- 运行 skill 结构和 frontmatter 校验。
- 用独立场景验证触发条件、评分、观察名单降级、压力位缺失和错误处理。
- 验证 skill 不会调用 TradingView 之外的行情源。
- 验证 `SKILL.md` 中的每个引用文件都存在且路由条件清楚。
- 从案例库随机选择案例，确认 Agent 能定位课程原文和所需图例，而无需默认加载全部笔记。
- 修改日报模板中的一个字段顺序，确认策略规则和评分结果不受影响。
- 运行确定性计算脚本的边界测试，包括 5%、8%、12%、2R 和零除保护。

### TradingView 试运行

- A 股、港股、美股各完成一次 UI 初筛。
- 每个市场至少复核一个候选的周线、日线、行业、枢纽、支撑、压力和相对成交量字段。
- 验证最终收缩、潜在亏损、距枢纽点和 2R 计算可复核。

### 报告场景

- 有接近买点候选、没有新突破。
- 有上一交易日首次突破。
- 最终收缩或潜在亏损为 8%–12%，触发降级说明。
- 压力位收益不足 2R。
- 股票创新高，无明确压力位。
- 三地没有新收盘数据。
- TradingView 登录失效、页面不可读或单个市场失败。

### 自动任务验收

- 自动任务处于启用状态。
- 调度为每天北京时间 08:00。
- 目标为当前 Codex 任务。
- 创建后核对下一次计划运行时间和任务提示词。

## 完成标准

- 设计规则被完整蒸馏为可发现、可验证的个人 Codex skill。
- Skill 可通过本机 TradingView 完成三地筛选和报告生成，不依赖其他行情源。
- 自动任务按北京时间每天 08:00 运行并向当前任务发送结果。
- 报告以观察名单为重点，避免重复旧突破，明确展示风险、赔率、降级原因和数据异常。
