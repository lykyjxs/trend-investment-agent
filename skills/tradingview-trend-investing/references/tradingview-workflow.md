# TradingView 全 UI 工作流

本工作流只操控本机浏览器中的 TradingView。按控件的可见文字、角色和当前状态定位，不依赖固定屏幕坐标。页面改版后先重新识别标签，不能盲点旧坐标。

## 运行频率

- 每周第一次运行：执行一次三市场全量检查，重新确认筛选条件、指数阶段和候选池。
- 其余每日运行：确认最近完整交易日是否更新，复用筛选逻辑，重点检查候选变化、接近枢纽和新突破。
- 北京时间 08:00 若三个市场都没有新的完整交易日数据，使用无新数据模板，不重复旧名单。

## 0. 运行前检查

1. 打开 TradingView，确认用户登录状态和股票筛选器可用。
   - 优先打开账号中已保存的“扫地僧过滤”筛选器；不要在每日运行时从零重建全部条件。
   - 浏览器实测账号可登录并读取 `A/H_share` 图表布局，但 Basic 方案在新建筛选器时自定义 SMA 周期会出现升级提示。若保存筛选器不存在或条件不可核实，按“筛选器条件失败”处理，不能改用近似周期。
2. 确认页面中的最后交易日期，而不是用当前日历日期推断数据已经收盘。
3. 读取同一 Codex 任务中最近一次日报：记录各市场数据日期、已报告的新触发名称和枢纽日期。
4. 若没有历史日报，标记为首次运行，新触发回看最近 5 个交易日；否则只检查上一完整交易日并去重。
5. 不打开任何替代行情站。TradingView 不可用时进入失败模板。

## 1. 三市场筛选器

依次切换 A 股（CN）、港股（HK）、美股（US）。每次切换后重新确认市场标签，防止筛选条件看似保留但数据市场未切换。

共同条件：

- 股票类型：普通股；
- 价格 > SMA50；
- SMA50 > SMA150；
- SMA150 > SMA200。

本币市值条件：

- A 股：总市值 > 400 亿 CNY；
- 港股：总市值 > 400 亿 HKD；
- 美股：总市值 > 400 亿 USD。

筛选器列至少显示：名称、行业/板块、现价、总市值、SMA50/150/200、成交量、相对成交量（或时间相对交易量）。英文 UI 实测列名为 `Symbol`、`Price`、`Vol`、`Rel vol`、`Mkt cap`、`Sector`；若字段名称因语言不同而变化，按语义查找 `Relative Volume`、`Rel vol`、`相对成交量` 或 `时间相对交易量`，不把普通成交量误当相对成交量。

市场切换实测标签为 `CN`、`HK`、`US`，市值列随市场分别显示 `CNY`、`HKD`、`USD`。免费/Basic 数据可带 15 分钟延迟标记；08:00 运行仍必须以最近一个完整交易日为数据截止点，不能把盘前价或未收盘报价当日线收盘价。

## 2. 大盘环境

先打开相应指数周线，再看日线：

- A 股：沪深 300；
- 港股科技类：恒生科技；港股其他：恒生指数；
- 美股科技类：纳斯达克 100（NDX）；美股其他：标普 500。

记录指数阶段、主要均线排列和方向。行业必须来自 TradingView；行业字段缺失时不能根据公司名自行归类。

## 3. 候选逐股复核

对每个初筛候选：

1. 周线判断长期阶段，识别 Stage 2、顶部或下跌风险。
2. 日线查看 50/150/200 日均线、相对大盘表现和一年高低位置。
3. 标出两到三次收缩、最终收缩的高低点与持续天数。
4. 标出最终稳固区上沿作为枢纽点。
5. 标出最近稳固区低点作为主要支撑，并在支撑下方少许给出止损参考。
6. 标出上方最近有效摆动高点作为压力；创新高没有摆动高点时记录“无明确压力位”。
7. 读取成交量和相对成交量，记录为状态而非评分。
8. 检查放量大跌、跳空下跌、跌破长期均线、高位异常阴线和宽幅无序震荡。
9. 把本次 TradingView 读取的现价、枢纽、支撑和压力输入计算脚本，不能让脚本自行获取数据。

建议先在内部工作表保存名称、市场、行业、数据日期和计算输入。股票代码只可用于在 TradingView UI 中准确定位，不得出现在给用户的日报中。

## 4. 计算

在 skill 目录运行：

```powershell
python scripts/calculate_trade_metrics.py '{"current_price":100,"pivot_price":105,"support_price":95,"pressure_price":120}'
```

创新高时把 `pressure_price` 设为 `null`。输出的正枢纽距离表示已突破，负值表示仍在枢纽下方。计算结果不舍入保存，报告显示时可统一保留一到两位小数。

## 5. 分类与去重

### 观察名单

只收当前价位于枢纽下方 8%以内、总分至少 60、最终收缩和潜在亏损不超过 12%的候选。应用固定降级说明后，每市场排序并截取前 10。

### 新触发

只收最近一个完整交易日首次越过枢纽、当前价位于枢纽上方 8%以内、最终收缩和潜在亏损均不超过 8%的候选。符合者全部列出。

- 首次运行：回看最近 5 个交易日，列出仍处于合理买入区的首次突破，建立基线。
- 后续运行：与同一任务最近报告比较，只列上一完整交易日新发生且以前未报告的突破。
- 不因赔率不足、大盘弱或量能不足删除新触发事实；使用对应警告。

## 6. UI 异常恢复

1. 控件未找到：重新获取页面状态，按可见标签或角色查找，不直接点击旧坐标。
2. 筛选器条件不确定：逐项展开条件并重新确认，不假设保存成功。
3. 页面加载不完整：刷新当前 TradingView 页面一次并重新检查数据日期。
4. 登录、订阅或市场权限阻塞：停止该范围的读取并记录明确错误。
   - 若自定义 SMA 周期弹出 `Get all screening capabilities` / `Upgrade`，先退出弹窗并检查已保存的“扫地僧过滤”；保存筛选器也不可用时记录失败，禁止用 SMA100、SMA200 等预设项拼成近似规则。
5. 单字段或单市场失败：继续其他市场，把失败范围放在“异常与缺失”。
6. 全部市场失败：使用失败模板，不输出旧候选冒充当日报告。

## 7. 发布前核对

- 每个数值都能回溯到本次 TradingView UI 或纯计算脚本。
- 没有使用搜索、其他财经网站、行情 API 或缓存旧值补缺。
- 观察在前、新触发在后；观察每市场不超过 10，新触发没有数量上限。
- 当前价相对枢纽的方向正确：观察为下方，新触发为上方。
- 8%/12% 降级和排除边界正确。
- 创新高时 2R 被标为目标而非压力。
- 报告没有股票代码，也没有任何已执行或将自动执行订单的表述。
